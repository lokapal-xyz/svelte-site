# YAML Glossary

*On a working example.*

The clearest way to explain a YAML Library is to walk through the one that already exists. The **YAML Glossary** holds every defined term and symbol in the treatise as a single set of structured records — one entry per concept, each carrying the same set of fields, cross-linked to related entries by a stable identifier. It replaced two separate prose glossaries — one for definitions, one for symbols — that had been drifting apart the way any two hand-maintained documents eventually do, each covering roughly the same ground with no way to catch a term defined in one but not the other, or a symbol used two different ways across chapters.

Each entry carries a small, consistent set of fields: a stable `id`, used for cross-referencing rather than the display name, which can be revised later without breaking a link; the `term` itself and its `symbol`, where one exists; which chapter (`part`) and, where relevant, which `jurisdiction` it belongs to; its `pair`, if it has one; its `equation`, where a term is derived from others rather than primary; a `definition`; and `related`, a list of other entries worth reading alongside it. A few entries also carry `notes` — caveats, historical context, or a flag that something about the entry needs attention.

That structure is already doing real work, not just organizational tidying. For example, it makes the treatise's own scope legible at a glance. A query as simple as "every entry belonging to Attributes Status" or "every entry with a flagged status" is immediate against the glossary and would require rereading whole chapters against the prose alone. As the treatise grows, that gap only widens.

The glossary's audience is not exclusively an AI's, and shouldn't be read that way. A person can open the file directly and get real use from it — this treatise's own author has done exactly that, spotting the symbol collision on inspection before any automated check ran. What the format adds on top of that is a second audience, native rather than accommodated: an AI assisting with the material (see AI Assistance) can hold the entire glossary in view at once, check a new term or symbol against it before introducing something that collides, and use it as the concrete substrate for the translation-between-representations capability described there — turning a compact entry into a full discursive explanation, or the reverse, on request.

The glossary is also meant to be read as a template rather than a finished, singular artifact. Its structure — stable ids, explicit fields, cross-links instead of prose references — is the same structure any future YAML Library instance described in YAML Library would follow: a case library's records would carry their own fields suited to a case reading, but the same underlying discipline of consistency, checkability, and accumulation without disorder. The glossary is simply the first place that discipline was applied, and the place where its usefulness stopped being theoretical.
